# Contributing

Contributions should preserve the repository's role as an open evaluation
protocol and methodology artifact.

## Good Contributions

- Documentation improvements.
- Scenario-schema clarifications.
- Scoring-spec clarifications.
- Additional public-domain examples with clear source provenance.
- Release-policy improvements.
- Paper edits that improve methodological clarity.

## Do Not Submit

- Private `fide-eval-engine` source code.
- API keys, provider credentials, or endpoint secrets.
- Raw model outputs containing sensitive or restricted content.
- Restricted source text.
- Partner traces or private product outputs.
- Claims that treat the protocol as a leaderboard, model ranking, product
  endorsement, theological certification, or legal opinion.

## Review Expectations

Before opening a pull request, check that new files do not include credentials,
restricted source text, held-out prompts, or private execution artifacts.
